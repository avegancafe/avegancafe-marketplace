# Manage a project's todo.md

Every project folder `_projects/YYYY-MM-DD--<name>/` has a `todo.md`.

## Format

```markdown
# TODO — <project name>

- [ ] Write the launch announcement @high [assignee:brave-otter]
- [ ] Collect beta feedback @medium
- [x] Set up the repo @low [assignee:quiet-harbor]
```

- One task per line: `- [ ]` open, `- [x]` done.
- **Priority** is an @-mention on the line: `@high`, `@medium`, or `@low`.
  One priority per task; add one if the user gives any signal about urgency,
  otherwise it may be omitted.
- **Assignee** is linked by id: `[assignee:<id>]`, where `<id>` is a readable
  adjective-noun session id (e.g. `brave-otter`) generated by the
  `session-ids` plugin. Zero or more assignees per task.
  - To assign the *current session*, get its id via the `session-id` skill
    from the `session-ids` plugin.

## Operations

- **Add a task**: append a `- [ ]` line under the heading with priority and
  assignee(s) as given. Don't reorder existing tasks unless asked.
- **Complete a task**: flip `- [ ]` to `- [x]`. Keep the rest of the line
  (priority, assignees) intact.
- **Reprioritize**: replace the `@high|@medium|@low` mention in place.
- **Assign / reassign**: add or replace `[assignee:<id>]` on the line.
- **Report**: when asked what's open, summarize open tasks grouped by
  priority (high first), noting assignees.

## Finding the right todo.md

If the user names the project, match the `<project-name>` part of the folder
(ignore the date prefix). If ambiguous, list the folders in `_projects/` and
ask. If the current working directory is already inside a project folder, use
that project's todo.md.
